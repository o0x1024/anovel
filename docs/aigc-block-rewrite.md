# AIGC 语义块改写与手动复检

一键改写采用“冻结检测证据、批量生成、用户手动复检”的两阶段流程，不再逐句贪心优化，也不在候选阶段反复运行检测模型：

1. 逐句检测提供风险和具体证据；
2. 当融合结果以疑似AI或AI为主时，整篇按目标约240字、最多6句组成连续场景块，短对白与动作、反应共同进入改写；
3. 模型先逐句诊断并提取必须逐字保留的事实锚点，再生成“场景重写”和“节奏重写”两个候选；
4. 候选必须完整保留事实锚点、数字和引号内对话，长度保持在原块的0.72至1.35倍；允许自由拆句、并句和重组段落；
5. 候选只执行确定性的生成质量门禁：整块改动至少24%、非对话叙述改动至少34%、长度、事实锚点、数字、引号内对话、段尾标点、超长句、重复短语和案例原句复制检查；
6. 在通过门禁的候选中，选择接近48%整块改动、55%非对话叙述改动且长度稳定的版本；
7. 块补丁使用原文起止位置作为稳定ID，允许块内重新分句并支持独立接受、拒绝和回滚；
8. 通过质量门禁的块必须覆盖至少85%的目标文本，否则整批拒绝应用；达标后返回“待重新检测”，用户接受并应用补丁，再手动点击一次“重新检测”。

当前每个块最多生成两轮，每轮两个候选。案例增强只向匹配场景提供成对案例，不再因为某一块缺少案例而留下整段原文。一键改写期间不调用困惑度模型、结构检测器或中文监督模型，界面不展示改写后的人工、疑似AI和AI特征比例，也不声明达到人工100%。最终分类只来自用户点击“重新检测”后运行的一次完整融合检测。覆盖不足或候选未通过质量门禁时明确停止，不用旧检测结果冒充新文本结果。

这样把两个职责分开：生成阶段负责事实稳定和改写质量，检测阶段负责对完整最终文本作一次一致评估。它避免每个候选都触发全文双模型推理，同时确保最终结论仍由正式检测链路给出。

## 验证

```bash
npm run test:aigc-rewrite
npm run test:aigc-supervised
npm run test:zhuque-alignment
npm run build
```

外部朱雀检测只用于冻结输出的盲测。校准文本成功不能作为泛化结论，必须换未参与实现的新文本复测，并同时检查可读性、人物事实、数字、对话和事件因果。
