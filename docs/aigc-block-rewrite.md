# AIGC 语义块改写与闭环复检

一键改写采用“冻结检测证据、语义块生成、全文双门禁复检”的闭环。检测用于定位风险和验证最终候选，生成模型不能修改检测结论，也不能把 AI 辅助文本声明为人工创作。

## 工作流

1. 完整融合检测提供片段风险、统计证据和中文监督模型证据。
2. 当融合结果未通过本地风险门禁时，按目标约240字、最多6句组成连续场景块；短对白与动作、反应共同进入改写。
3. 模型先提取必须逐字保留的事实锚点，再生成“场景重写”和“节奏重写”两个候选。
4. 每个候选先过确定性的生成质量门禁：改动幅度、长度、事实锚点、数字、引号内对白、标点、超长句、重复短语和案例复制检查。
5. 通过质量门禁的整篇候选再运行一次正式融合检测。满足 AI 特征覆盖为0、疑似AI覆盖不高于15%、双检测器分歧覆盖不高于40%时才允许自动应用。
6. 未通过时将失败原因反馈给下一轮；全文最多3轮，句级入口最多4轮。达到上限后保留原文，不把失败候选写回编辑区。
7. 成功结果明确记录 `ai_assisted` 来源。界面中的人工、疑似AI和AI百分比仅表示当前本地检测器的特征覆盖，不表示作者身份，也不宣称“人工100%”。

块补丁仍以原文起止位置作为稳定 ID，允许块内重新分句。每轮生成阶段不对两个块候选逐个运行重型检测，只对通过整批质量门禁的完整候选复检，从而控制推理成本，同时避免用旧结果代表新文本。

这里的15%和40%是自动应用的产品风险阈值，不是检测准确率，也不是外部平台通过保证。外部朱雀只用于冻结版本的盲测；不得把外部检测结果作为单篇改写循环的优化反馈。

## 验证

```bash
npm run test:aigc-rewrite
npm run test:aigc-supervised
npm run test:zhuque-alignment
npm run build
```

发布前必须用未参与开发的分层文本检查可读性、人物事实、数字、对话、事件因果，以及人工误报率、AI召回率、Macro-F1、检测器分歧率和校准误差。
